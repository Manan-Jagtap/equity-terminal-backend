## What shipped

### A — Daily Dhan top-up (the stale-history fix)
`HistoricalPrice` had gone stale (last row 2026-05-29 — the one-off backfill was
never fed). The daily 10:15 UTC job now runs an incremental Dhan top-up
(30-day window, idempotent, self-rate-limited, zero WebSockets) for the visible
universe, then a **snapshot sync** that marks any name whose `MarketSnapshot`
is older than Dhan's latest close (IndianAPI's same-day marks are never
overwritten). Files: `app/dhan/backfill.py` (`days=` param,
`sync_snapshots_from_history`), `scheduler.py` (`run_dhan_topup`).

### B — Second-source cross-check (the accuracy spine, surfaced)
`GET /api/quality/cross-check` — Dhan (`HistoricalPrice`) vs IndianAPI
(`MarketSnapshot`) closes, straight from the DB (zero vendor calls, 5-min cache):
- `STALE_HISTORY` / `STALE_SNAPSHOT` — a source silently stopped updating.
- `DIVERGENT` — vendors disagree >6% (warn) / >20% (alert — split-shaped, the
  Bajaj-Finance class of bug, now caught automatically).
Frontend: a **Data health** strip on the dashboard (one-line all-clear when
clean; flagged names expand into a clickable list).
Files: `app/cross_check.py` (pure, tested), `app/quality_routes.py`,
frontend `MarketDashboard.jsx`.

### C — Factor engine on the 5-yr series
`assemble_factor_rows` now prefers **split-adjusted** `HistoricalPrice` closes
(windowed ~420d, adjusted with the same corporate-action ledger the chart uses —
a split inside the window can't fake a −50% momentum print). Momentum upgrades
to the canonical **12-1** (231d lookback, 21d skip) when a year of data exists,
vol window widens to **252d**; both fall back gracefully on short series.
Files: `app/factors.py` (`momentum()`), `app/signals.py` (`_adjusted_closes_by`).

### D — Universe tiers (Nifty 500 machinery, flip = one env var)
Official membership from **niftyindices.com** IndexConstituent CSVs (fetched
2026-07-04): `NIFTY_MIDCAP_150` (137 new names) + `NIFTY_500_REST` (264).
`UNIVERSE_TIER=nifty100|nifty250|nifty500` selects `VISIBLE_UNIVERSE`
(default nifty100 — today's behaviour, bit-identical). Key design points:
- IndianAPI daily EOD is pinned to the new `CORE_UNIVERSE` (Nifty 100), so a
  wider tier costs **zero** IndianAPI quota — wider names are priced by the
  Dhan top-up + snapshot sync (A).
- `EXCLUDED_TICKERS = {"INDIGO"}` — the "better hidden than mis-priced" rule
  survives every tier.
- `/api/universe` now reports the live tier.
- **Membership drift caught in the data:** the official Nifty 500 no longer
  lists TATAMOTORS — it demerged into TMPV/TMCV (both in the new sets). The
  Nifty-50 ingest set still carries TATAMOTORS; decide the successor before
  the next relaunch.
Files: `app/ingest/indianapi_ingester.py`, `app/main.py`,
`tests/test_universe_tiers.py`.

### E — Shareable scenario links
`POST /api/scenarios/{id}/share` mints a **stateless HMAC token** (signed with
`AUTH_SECRET`, no schema change); `GET /api/scenarios/shared/{token}` is a
public read-only view (ticker/name/data — never the owner; 404 for bad tokens
and deleted scenarios alike). Frontend: a link icon on each scenario chip
copies a deep link; `?scenario=<token>` at App boot opens the company with the
shared assumptions overlaid on its own.
Files: `app/scenario_routes.py`, `tests/test_scenario_share.py`,
frontend `ScenarioBar.jsx`, `App.jsx`.

### F — Portfolio risk block (the survival math)
`/api/portfolio/xray` now returns `risk`: **historical 95% VaR** (1-day, % and
₹), **max drawdown** (trailing year, peak→trough dates), **XIRR**
(money-weighted, from each holding's `added_at` cashflow), plus series
coverage. Built on the split-adjusted Dhan series; every statistic **degrades
to None** on thin data (VaR needs ≥60 obs, XIRR ≥30 days span) — the terminal
never fabricates a risk number. Frontend: a risk card row in the X-ray panel.
Files: `app/portfolio_risk.py` (pure, tested), `app/portfolio_routes.py`,
frontend `Portfolio.jsx`.

### G — Saved screens
Named screener presets (query/sector/sort as a schemaless dict), auth-scoped
like scenarios. New `SavedScreen` table (additive), `/api/screens` CRUD,
save/apply/delete chips in the Screener.
Files: `app/models.py`, `app/screens_routes.py`, frontend `Screener.jsx`.

## Post-deploy addendum (same day)

The live cross-check immediately caught a real pre-existing bug: **all 101
snapshots flagged STALE_SNAPSHOT** because `MarketSnapshot.as_of` was only ever
set on insert (server_default) — every price update left the creation
timestamp in place, so freshness was unknowable. Fixed: `_price_from_stock`
now stamps `as_of` on every update. This also protects the new Dhan
snapshot-sync from overwriting prices IndianAPI just refreshed. The
STALE_SNAPSHOT alerts clear on the first intraday/EOD run after this deploys;
STALE_HISTORY warnings clear when the first daily Dhan top-up runs.

Also added an option-chain probe + full Dhan error bodies to /api/dhan/status
(the chain endpoints still 401'd after the client-id fix — the probe now shows
Dhan's own error code, which says whether it's a bad client-id or a missing
Data-plan subscription).
